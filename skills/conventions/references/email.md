# conventions (email)

## The address in git

Commit author and committer e-mail is the GitHub noreply address, never the user's real one (`rules (identity)`). It is checked with
the scan before every public push; it is never written into a README, a license, a header comment or a doc as a contact.
In a cloud session set the repo's own `user.name`/`user.email` before the first commit.

## E-mails the user sends or has drafted

- A draft is a file or a draft in the mail tool; sending is outward-facing, so only on the user's word for that message.
- Plain full sentences (`docs`), the answer or the ask in the first line, one topic per mail, subject that says it.
  Write in the recipient's language unless the user says otherwise.
- No `[Your Name]`-style placeholders in a finished draft; no phone number as the contact channel in client material
  (e-mail and messengers only).
- The signature carries the public handle only where a public persona is the point; client work uses the
  sender details the user gives for that client.
- Never paste secrets, tokens or personal data into a mail or into any external service to "test" it.

## Gaps

Nothing here was dictated as a rule beyond the points above; extend this file when the user states a convention (subject
format, signature, reply style).
