# cleandocs

Docs are code that nobody compiles; this skill is the compiler. The wording rules are `conventions (docs)`, the
public-facing scan is `publish-anything`; here is the pass that finds and fixes what drifted.

## Pass

1. **Inventory.** `git ls-files '*.md' '*.txt' '*.rst'` plus every `--help` text and man page. Count them first
   (`wc -l`), then read by intent (`code (reading)`).
2. **Classify each file** into one of four and act:
   - *Keep*: describes the code as it is now.
   - *Fix*: right idea, wrong detail (a renamed flag, a moved path, an old number).
   - *Move*: notes, braindumps, todo lists, questions, "his words" - they belong in the notes repo
     (`claude-config/braindump.md`), never in a project repo, least of all a public one.
   - *Retire*: duplicated, superseded, or about something gone. It goes to the trash folder, not to `rm`
     (`rules (trash-not-rm)`); history keeps the rest.
3. **Check every claim against the code.** Each command in a README or doc is run (or `--help`'d) once; each path
   exists; each flag, env var and option name is found by `rg`; each number is measured again or dropped
   (`rules (rtfm)`, `code (done)`). A doc line that cannot be checked is rewritten until it can.
4. **Check the links.** Relative links point at files that exist (a loop over `rg -o '\]\(([^)#:]+)'` results and
   `test -e`); anchors match a heading; an external link is kept only when it is the primary source.
5. **One README per folder** that holds code or data: what it is, how to run it, the one gotcha; its list of files
   matches `ls`. A folder with nothing to say gets none rather than a stub.
6. **Wording.** Run `publish-check` (filler, emoji, "robust", "seamless", "honest gap"), then the tone: plain
   sentences, a number next to every claim, no sales words, no history in comments, no step numbering of obvious
   things. Headings state what the section holds.
7. **Sync the generated parts.** An index, a coverage table or a command list that is produced by a script is
   regenerated by the script, not edited by hand.
8. **Tests still pass** and the repo's `check` / `test` scripts run clean; a doc change that breaks a doc test is
   a doc bug.

## Report

Five lines in the reply: files kept / fixed / moved / retired, what was run to verify, what is left and why.
Commit as `docs: ...` in small steps (moves apart from rewording), so a wrong call is one revert.
