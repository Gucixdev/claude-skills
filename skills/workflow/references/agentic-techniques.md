# workflow (agentic-techniques)

- **AFK loop**: when the user is away or I am idle, take the next item from the doing list / braindump that needs little of the user's help; keep going, report at the end (see task-stack and afk-loop).
- **Orchestrator**: I plan and review; forks do bulk work. A fork gets a NEW CLEAN session with a self-contained prompt: goal, paths, conventions, safety rules, what NOT to touch, report format (<=14 lines). Never hand it my whole history. Few forks, disjoint files, no duplicates.
- **Cheap labour**: free providers (`workflow (openrouter)`) for bulk drafts, councils, second opinions.
- **Safety defaults in every fork prompt**: no `git add -A` in dirty repos, no push without the user's OK, no rm (move to the trash), never touch the live compositor, editor or login manager, tests in namespaces/private buses, honest tested-vs-untested report.
- **Defence over offence** for anything security-flavoured.
- Repeated action -> make it a tool/skill immediately.
