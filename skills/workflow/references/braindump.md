# workflow (braindump)

A dump is for catching, not deciding. Building the first idea while four more wait loses the four.

1. **Capture first**: one line per idea, the user's wording kept (typos fixed, nothing added), in `braindump.md` at the repo root
   of the project it belongs to, or `~/dev/braindump.md` when it belongs to none. Append; never reorder what the user wrote.
2. **Mark each**: `[ ]` open, `[~]` stub (a folder or file exists, empty), `[x]` done with the commit or path, `[?]` needs
   one fact from the user. A line that is really several wishes is split.
3. **Group at the end**, not while the user talks: by project, then by what blocks what. Show the groups in 5-10 lines.
4. **Do not build during the dump.** Build when the user says go, or when working alone (afk-loop): take the group that
   unblocks most, one at a time, tick the line when done.
5. Duplicates of an older line are merged by pointing at it, not deleted. One braindump file per place, never two.
6. Empty-stub batches are mine to fill and organise (when the user has allowed it); a deletion of any of the user's lines is not.
