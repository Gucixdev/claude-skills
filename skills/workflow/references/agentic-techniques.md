# workflow (agentic-techniques)

- **AFK loop**: when the user is away or I am idle, take the next item from the doing list / braindump that needs little of his help; keep going, report at the end (see task-stack, feedback "keep working autonomously").
- **Orchestrator**: I plan and review; forks do bulk work. A fork gets a NEW CLEAN session with a self-contained prompt: goal, paths, conventions, safety rules, what NOT to touch, report format (<=14 lines). Never hand it my whole history. Few forks, disjoint files, no duplicates.
- **Cheap labour**: free providers through the openapi MCP / openrouter skill for bulk drafts, councils, second opinions; burn leftover limit at 04:20 reset on useful work.
- **Safety defaults in every fork prompt**: no `git add -A` in dirty repos, no push without his OK, no rm (move to the trash), never touch live dwl/frost/Godot/logind, tests in namespaces/private buses, honest tested-vs-untested report.
- **Defence over offence** for anything security-flavoured.
- Repeated action -> make it a tool/skill immediately.
