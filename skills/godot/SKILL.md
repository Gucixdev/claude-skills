# godot

## Conventions

- Addons as one self-contained node that does the whole job (Control3D, SaveSystem, AnimPlayer, DialogueSystem were
  each collapsed to one node, 2026-10-10) - easy to drop in, reason about and delete.
- No `ez*` prefix here (that is his bash tools' convention); name nodes for what they do.
- Godot's own nodes and features before a third-party addon - `core/` is mid-purge of plugins.
- External editor is Emacs: `~/.config/godot/editor_settings-4.7.tres`, `text_editor/external/exec_path` =
  `emacsclient`. Running from Emacs: `C-c r` runs `compile-command`, set per project in `.dir-locals.el`
  (`godot --path /path/to/project`). `godot` is on PATH.
- Data-heavy code: `PackedArray`s and the servers API over thousands of nodes (`code (languages)` (dod)).

## Connections (both start with the app)

- Godot: toolbox tool `godot_mcp_server` on port 9090 (next free up to 9094) in any project with `addons/toolbox`
  enabled (core, scrollsouls, web; `new_project.sh` sets it up). Bridge `~/dev/godot/core/godot-mcp-bridge.mjs`,
  reconnects lazily. Several editors: `godot_instances`, then `godot_use {project}`; `godot_status` for health.
- Blender: add-on server on 9876, started by `~/.config/blender/mcp/blendermcp_autostart.py` on every GUI launch.
  After installing a new Blender version run `~/.config/blender/mcp/run` once. `blender -b` never serves.

## Godot tools (106+, generated by `python3 ~/dev/godot/core/mcp_tools/gen_tools.py`)

Load with ToolSearch `select:mcp__godot__godot_NAME`. Groups: scene (read_scene, get_scene_hierarchy, add/remove/move/
rename_node, modify_node_property, set_node_properties, attach_script, set_material/mesh, connect_signal, groups),
file and script (read_file, list_dir, search_project, create_script, edit_script, validate_script), project
(get_errors, get_console_log, run_scene/stop_scene/is_playing, get_project_settings, update_project_settings,
setup_autoload, input map, classdb_query, rescan_filesystem), ui_*, theme_*, animation_*, animtree_*, particles_*,
nav_*, recording_*, export_*, test_assert, map_project. `godot_cmd {method, params}` is the raw escape hatch. Scene
paths `res://...`, node paths relative to the scene root ("UI/bars/hp"). Use these instead of headless scripts for
scene, node, UI and animation work (he asked for it, 2026-10-10).

## Blender to Godot

1. In Blender (`mcp__blender__execute_blender_code`):
   `import os; exec(open(os.path.expanduser("~/.config/blender/mcp/to_godot.py")).read())`, then
   `print(export_to_godot(os.path.expanduser("~/dev/godot/core"), "crate"))` (selected; or `collection="Props"`,
   `selected_only=False`) - writes `PROJECT/assets/models/NAME.glb` (Y-up, modifiers applied, materials embedded),
   returns res_path, triangles, warnings.
2. In Godot: `godot_rescan_filesystem {paths: [res_path]}` (waits for the import).
3. `godot_instance_scene {scene_path, instance_path: res_path}` or add_node, then `godot_save_scene`.
4. Verify: `godot_get_errors`; `mcp__blender__look` for the Blender side.

## Rules, each one paid for

- Never test new or changed plugin code against his live editor: a bad call aborted it (SIGABRT, unsaved work at
  risk). Test in a disposable instance: `bash core/new_project.sh iso` in a temp layout (symlinks the same toolbox),
  `godot --headless --editor --path ISO`, drive it with the bridge from a node script, then trash it.
- Before any headless crash test: `pgrep -af godot`. If his editor has the same project open, don't start a second
  one - two editors on one project fight over `.godot/` and the lock, and the crashes look like a code bug. Ask him to
  close it or wait.
- Never call `EditorFileSystem.update_file()/reimport_files()` right after `scan()` or during a scan; scan and wait.
- Never block the editor thread on a child process (`OS.execute`); `OS.create_process`, a log file, a status poll.
- Godot's JSON leaves raw control characters unescaped; a dropped message looks like a hang - strip or parse
  tolerantly.
- Writes change his OPEN scene (undoable): say what changes; read-only calls are free.
- After changing the bridge file the running MCP client keeps the old code until `/mcp` reconnects or the session
  restarts.
- Pixel and shader regression stays in `tests/render_*.gd` (windowed Vulkan harness), not in MCP.
