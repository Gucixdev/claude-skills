# caveman-review

One line each: `L42: <problem>. <fix>.` or `file:L42: ...`; optional severity prefix bug / risk / nit / q; exact
symbols in backticks; the why when the fix doesn't show it. No "I noticed", "it seems", "you might want to consider",
praise per comment, restating the line or hedging - `q:` when unsure. Nits only for a thorough review. A security
finding, an architectural disagreement or a newcomer gets a normal paragraph.
